# 전략서 — 한국어 경어법 × LLM 후속 연구 설계

- 승인일: 2026-09-19 (사용자 승인 "좋아 진행해줘")
- 이 문서는 **무엇을 왜 이렇게 만드는가**를 적는다. 누가 언제 무엇을 했는지는 루트의 `인수인계서.md`, 작업 단위의 절차는 `docs/01_실행계획.md`가 맡는다.

## 1. 의뢰 내용

선행 논문 10편을 단어·문장·문단·맥락 단위로 분석해, 그 논문들을 **계승하는 후속 연구**를 설계한다.

| # | 요구 | 이 프로젝트에서의 해석 |
|---|---|---|
| 1 | 논문을 4개 단위로 분석 → 후속 연구 설계 | 논문마다 같은 틀(6하원칙 카드 + 4층 분석 + 계승 지점)로 큐레이션한 뒤 횡단 분석으로 공백을 찾는다 |
| 2 | 실험 방법·실험 문장은 2×2 요인설계 | 모든 실험이 요인 2개 × 수준 2개이고, 가설 검정은 **상호작용항**에 건다 |
| 3 | 평가는 이해 문항 또는 Likert 척도 | 인간과 모델에 **문자 그대로 같은 과제**를 준다. surprisal은 핵심에서 제외 |
| 4 | 언어모델 추천 (구독형이 용이) | **상용 API(종량제)** 로 호출 가능한 모델 중심. GPU가 필요한 로컬 모델은 보조 |
| 5 | 국어학적 함의 | LLM 실험 결과가 한국어 경어법 이론의 어느 쟁점에 증거가 되는지를 설계 단계에서 미리 연결 |

최종 산출물은 ① DOCX 보고서 1벌, ② 6하원칙 6개 관점 탭 중심의 HTML 대시보드, ③ 모든 작업을 추적하는 인수인계서다.

## 2. 기존 자료(2026-09-18 초안)의 문제와 대응

| 문제 | 대응 |
|---|---|
| 산출물이 작업 순서(분석→설계→문서)로 나열돼 독자의 질문 순서와 어긋남 | 모든 산출물을 6하원칙으로 재편 |
| 논문 분석이 긴 마크다운 한 장, 논문마다 항목이 달라 비교 불가 | 논문 카드 스키마(`docs/02_논문카드-스키마.md`)로 통일 |
| HTML이 재검증 보고서 한 장뿐 | 연구 설계 전체를 담는 탭형 대시보드 |
| 검증이 사후에 이뤄져 정정 11건 발생 | 생성자≠검증자, 쪽수 앵커 자동 검사 |
| surprisal·로컬 모델·미세조정 중심 설계 | 상용 API + 행동 평가(Likert·이해 문항) 중심으로 재설계 |
| 인수인계서가 사후 요약 | 작업 대장·의사결정·검증 기록을 갖춘 추적 문서 |

기존 자료는 `reference/`에 두고 **참고만** 한다(커밋 제외). 기존 분석의 "핵심 발견"도 전제로 삼지 않고 원문에서 다시 확인한다.

## 3. 운영 원칙

1. **6하원칙 단일 뼈대** — 논문 카드, 대시보드 탭, 보고서 장 구성, 인수인계서 작업 기록이 모두 같은 여섯 칸(누가·언제·어디서·무엇을·어떻게·왜)을 쓴다.
2. **근거 앵커** — 논문에 대한 모든 서술에 논문 ID와 PDF 쪽수를 붙인다. 원문 인용은 15단어 이내 핵심 구절만, 나머지는 의역한다.
3. **생성자 ≠ 검증자** — 분석을 쓴 에이전트와 다른 에이전트가 수치·인용을 원문과 대조한다. 기계적으로 확인할 수 있는 것(쪽수 범위, 인용 구절·수치의 해당 쪽 존재 여부)은 스크립트가 검사한다.
4. **단일 원천** — `content/`의 구조화 데이터에서 DOCX와 대시보드를 함께 빌드한다. 두 산출물의 내용이 어긋나지 않는다.
5. **인수인계서 단일 작성자** — 병렬 에이전트는 파일만 만들고, 인수인계서는 메인 세션만 고친다.

## 4. 6하원칙 적용

| 관점 | 논문 카드(10편 공통) | 대시보드 탭 | 인수인계서 작업 기록 |
|---|---|---|---|
| WHY 왜 | 문제의식·한계·우리가 계승할 지점 | 선행연구의 합의·불일치·공백, 국어학적 함의 | 판단 근거 |
| WHAT 무엇을 | 연구 질문·핵심 주장·주요 수치 | 연구 질문·가설·2×2 실험 세트·자극 브라우저 | 산출물 |
| WHO 누가 | 저자 / 실험 대상(모델·인간) | 모델 추천 라인업 + 인간 기준선 + 검수자 | 담당 모델·에이전트 |
| WHEN 언제 | 발표 시점 / 실험 모델의 세대 | 로드맵, 모델 버전 고정 시점 | 일시 |
| WHERE 어디서 | 발표처 / 데이터 출처·공개 자료 | API 실험 환경·사전등록·투고처 | 파일 경로·커밋 |
| HOW 어떻게 | 자극·측정·통계 | 프롬프트 절차·Likert·이해 문항·분석 모형·통제 | 방법·검증 결과 |

대시보드는 홈(6하원칙 × 5영역 매트릭스) + 6개 관점 탭 + 보조 탭 2개(논문 서가, 진행 추적)로 구성한다. 5영역은 연구 설계·실험 전략·평가 방법·모델 추천·언어학적 함의다.

## 6. 연구 설계 접근

채택: **C안 — 공통 가설 + 3현상 + 통제 실험 1개.**

"모델은 경어 형태의 **표면 공기(共起)** 를 학습했는가, 경어 사용의 **허가 조건**을 학습했는가"라는 하나의 가설을 서로 다른 세 현상에서 같은 평가 절차로 검정한다. 두 가설은 주효과에서는 같은 예측을 하고 **상호작용항에서만 갈리므로** 2×2가 필요하다. 여기에 프롬프트 메타언어 통제 실험 1개를 더한다(P01의 "옳은 답, 틀린 이유" 문제를 계승).

기각한 안 — A(주체높임 `-시-` 한 현상만 2×2 연쇄로 해부): 계승성은 최고지만 국어학적 함의의 범위가 좁다. B(경어법 하위 체계마다 2×2 하나씩): 범위는 넓지만 실험 간 연결이 약해 한 편의 논증이 되지 않는다.

실험 후보는 6–8개를 만든 뒤 여섯 기준으로 선별한다: ① 계승성(어느 논문의 어떤 한계를 잇는가) ② 최소대립쌍 구성 가능성 ③ API 행동 평가로 측정 가능한가 ④ 국어학적 함의의 크기 ⑤ L1 화자 직관의 안정성 ⑥ 자극 제작 비용. **최종 실험 세트는 논문 분석이 끝난 뒤 확정하며 사용자 승인을 받는다(승인 지점 ①).**

## 7. 평가와 모델 (상용 API 전제)

- **과제**: 7점 Likert(수용성·공손성) + 이해 문항(4지선다: "화자가 높이는 대상은 누구인가", "누가 더 윗사람인가" 등). 인간용 지시문과 모델용 프롬프트를 같은 문장으로 쓴다.
- **API 운영 통제**: 시행마다 새 컨텍스트(이월 효과 차단), 모델 ID의 날짜 스냅샷 고정, temperature 정책과 반복 표집 수, JSON 구조화 출력, 제시 순서 무선화, 추론(thinking) 모드는 모델 수준 공변인으로 기록, 호출 비용 추정.
- **모델 추천 3계층**: 글로벌 프런티어(OpenAI·Anthropic·Google) / 한국어 특화 상용 API / 호스팅 API로 쓰는 공개 가중치 모델. 모델 사양·가격·API 제공 여부는 작성 시점에 **공식 문서로 확인하고 URL과 확인일을 기록**한다.
- **선택적 확장**: 로그확률을 제공하는 API에 한해 surprisal을 보조 지표로 둘 수 있다. 핵심 설계에는 넣지 않는다.
