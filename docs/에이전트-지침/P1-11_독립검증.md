# P1-11 에이전트 지침 — 논문 카드 독립 검증

당신은 논문 카드를 **쓰지 않은** 검증 담당이다. 맡은 카드의 사실 주장을 원문과 하나씩 대조해 틀린 곳을 고치고, 무엇을 확인했고 무엇을 고쳤는지 기록한다. 카드의 문체나 해석을 다시 쓰는 것이 목적이 아니다. **원문과 어긋나는 사실**을 잡는 것이 목적이다.

## 입력

- 카드: `content/papers/P??.json` (규격은 `docs/02_논문카드-스키마.md`)
- 원문: `papers/txt/P??.txt`(쪽 표지 `===== [P?? p.N/총쪽] =====`), `papers/txt/P??.layout.txt`(표), `papers/pdf/P??_*.pdf`(그림·표는 Read 도구의 `pages` 인자로 직접 본다)

## 대조 범위 (전수)

1. `key_numbers` 전부 — 값·단위·쪽수. `(그림 판독)`이 붙은 값은 PDF 그림을 직접 보고 확인한다. `(재계산)`이 붙은 값은 산식을 다시 계산한다.
2. `layers.sentence` 중 `kind`가 `result`·`claim`·`hypothesis`인 항목 전부 — 인용 구절이 원문 그대로인지, `paraphrase_ko`가 원문의 뜻을 바꾸지 않았는지(특히 결론의 세기: 저자는 "suggest"라고 했는데 카드는 "입증했다"라고 쓰지 않았는지).
3. `design` 전부 — 조건 수, 요인·수준, 문항 수, 모델 이름·규모, 참여자 수, 척도, 통계 모형.
4. `successor_hooks` 전부 — `basis_ko`가 원문에 근거하는지. 저자가 밝힌 후속 과제라고 적었다면(`author_future_work`) 원문에 실제로 그 문장이 있는지.
5. `citation` — 저자 표기, 연도, 발표처, 권호·쪽, DOI. DOI는 WebFetch로 `https://doi.org/<DOI>`가 해당 논문으로 연결되는지 확인한다.
6. `w5h1`의 `who`·`when`·`where` 항목 전부(사실 항목이라 틀리기 쉽다).

## 기록

- 틀린 곳은 카드를 직접 고친다.
- 카드의 `verification`을 `{"status": "verified" | "corrected", "by": "P1-11 Opus 검증", "notes": [...]}`로 채운다. `notes`에는 고친 항목마다 `"<경로>: <이전> → <수정> (근거 p.N)"` 형식으로 한 줄씩, 그리고 마지막에 `"대조 범위: key_numbers N건, sentence M건, design, hooks K건, citation, w5h1 사실 항목"` 한 줄을 적는다. 하나도 안 고쳤으면 `verified`, 하나라도 고쳤으면 `corrected`.
- 고친 뒤 `python3 build/validate_cards.py P??`로 오류 0을 확인한다.
- git 명령을 실행하지 않는다. 맡은 카드 외의 파일은 고치지 않는다.
