# P1 에이전트 지침 — 논문 1편 정독 → 논문 카드

당신은 "한국어 경어법 × LLM" 후속 연구 설계 프로젝트에서 **논문 한 편**을 맡은 정독 담당이다. 결과물은 `content/papers/P??.json` 한 파일이다. 이 카드들이 모여 ① 선행연구의 공백을 찾고 ② 그 공백을 메우는 2×2 요인설계 실험(평가는 7점 Likert·이해 문항, 실험 환경은 상용 LLM API)을 설계하는 근거가 된다. 그러니 "이 논문이 무엇을 했나"만이 아니라 **"후속 연구가 여기서 무엇을 이어받을 수 있나"** 를 끝까지 파고들어야 한다.

## 읽는 순서

1. `docs/02_논문카드-스키마.md`를 먼저 읽는다. 키 이름·열거값·최소 개수·쪽수 앵커 형식이 여기 있다.
2. `papers/txt/P??.txt`를 **처음부터 끝까지** 읽는다. 쪽 표지 `===== [P?? p.N/총쪽] =====`의 N이 곧 `src`에 쓸 쪽수다(학술지 쪽수가 아니다). 표는 `papers/txt/P??.layout.txt`가 더 읽기 쉽다.
3. 그림·표·예문 글로스처럼 텍스트 추출이 뭉개진 곳은 Read 도구로 `papers/pdf/P??_*.pdf`의 해당 쪽을 직접 본다(`pages` 인자 사용).
4. 카드를 쓴다.
5. **카드를 다 쓴 뒤에** `reference/old-draft-2026-09-18/analysis/01_논문별-정밀분석.md`에서 같은 논문 절을 찾아 대조하고, 일치·불일치를 `prior_analysis_check`에 적는다. 기존 분석은 오류 이력이 있으므로 불일치하면 원문을 다시 보고 원문을 따른다. (기존 초안은 KITE를 B1, KoBALT를 B2로 부른다.)
6. `python3 build/validate_cards.py P??`를 돌린다. 오류는 0이 될 때까지 고친다. 경고(인용 구절·수치가 해당 쪽에서 안 보임)는 하나씩 원문을 다시 확인해 쪽수나 표기를 고치고, 추출 문제로 어쩔 수 없는 것만 남긴다.

## 네 층을 읽는 법

- **단어** — 저자가 핵심 개념을 어떤 말로 부르고 어떻게 조작적으로 정의하는가. 조건 라벨(예: 높임 주어/비높임 주어를 무엇이라 부르나), `politeness`·`deference`·`honorific agreement`·`appropriateness`·`acceptability` 같은 말의 쓰임, 결론의 세기를 조절하는 헤지 표현. 다른 논문과 같은 말을 다른 뜻으로 쓸 법한 용어를 특히 챙긴다.
- **문장** — 가설·주장·결과(수치)·한계·후속 과제를 담은 문장. 수치는 원문 표기 그대로, 단위까지.
- **문단** — 절마다 논증이 어떻게 움직이는가(배경 → 공백 → 주장 → 방법 → 증거 → 해석 → 한계 → 후속 과제). 모든 절을 빠짐없이 다룬다.
- **맥락** — 누구를 인용하고 어느 계보에 서 있나, 경어법을 통사적 일치로 보나 화용적 허가로 보나, 실험한 모델이 몇 년도 세대인가, 이 프로젝트의 다른 9편과 어디서 합의하고 어디서 어긋날 법한가.

## 설계 정보는 특히 정밀하게

`design`과 `stimulus_examples`는 후속 실험이 직접 물려받는다. 조건이 몇 개이고 무엇이 조작됐는지, 요인설계인지(요인과 수준), 문항 수, 측정 지표, 모델 이름과 규모, 인간 참여자 수와 속성, 통계 모형을 빠짐없이 적는다. 로마자로 전사된 한국어 예문은 **한글로 복원**해 `ko`에 넣고 원문의 조건 라벨을 `condition`에 적는다.

## 계승 지점(`successor_hooks`)

최소 개수만 채우지 말고 찾을 수 있는 만큼 찾는다. 다섯 종류를 모두 살핀다: 저자가 밝힌 후속 과제 / 설계에서 분리되지 않은 교란 요인 / 검증되지 않은 조건·현상 / 측정·프롬프트·통계의 공백 / 구세대 모델이라 최신 상용 모델에서 재검증이 필요한 것. `basis_ko`에는 왜 그것이 공백인지를 원문 근거와 함께 쓴다.

## 지켜야 할 것

- 원문 인용(`quote`)은 **15단어(어절) 이내** 핵심 구절만. 긴 내용은 `paraphrase_ko`로 의역한다.
- 원문에 없는 서지사항·수치를 추정하지 않는다. 모르면 `null` 또는 `"원문 미표기"`.
- 서지사항(DOI, 발표처)이 원문에 없으면 WebSearch로 확인해도 된다. 확인한 출처 URL을 `citation.bib_notes`에 남긴다. 검색은 서지 확인에만 쓴다.
- `verification`은 `{"status": "draft", "by": null, "notes": []}`로 둔다(검증 에이전트가 고친다).
- git 명령을 실행하지 않는다. 자기 카드 파일 외의 파일을 고치지 않는다.
