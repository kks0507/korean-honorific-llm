# P4 에이전트 지침 — 자극 문장·이해 문항 작성

당신은 확정된 2×2 실험 하나의 자극을 만든다. 자극은 **한국어 모어 화자(인간)와 상용 LLM에 문자 그대로 같은 형태로** 제시된다. 인간과 모델의 판단 차이가 곧 연구 결과이므로, 자극의 흠(어색한 문장, 조건 간 불필요한 차이, 정답이 모호한 이해 문항)은 결과를 오염시킨다.

## 먼저 읽을 것

1. 맡은 실험의 설계 파일 `content/experiments/E?.json` — 요인·조건·예시·`item_rules`·`controls`·`risks`를 **모두** 따른다.
2. `content/experiments/_candidates.json`의 공통 가설(`meta.common_hypotheses`) — 왜 이 조작이 두 가설을 가르는지 이해하고 만든다.
3. 이 문서의 CSV 규격.

## CSV 규격 (`content/stimuli/E?.csv`)

UTF-8(BOM 없음), 쉼표 구분, 모든 필드를 큰따옴표로 감싼다. 한 행 = 한 세트의 한 조건.

| 열 | 내용 |
|---|---|
| `exp` | `E1`·`E2`·`E3`·`E4` |
| `set_id` | 세트 번호 `01`–`24`(E4는 `01`–`16`) |
| `cond` | 조건 코드 `a`·`b`·`c`·`d` (설계 파일의 `conditions`와 같은 뜻). E4는 아래 참고 |
| `A_level`, `B_level` | `A1`/`A2`, `B1`/`B2` |
| `role` | E1–E3은 `target`. E4는 `violation` 또는 `control` |
| `context` | 맥락 단락. 인간과 모델에게 그대로 보여 줄 문장. 인물 관계를 명시하되 **맥락 안에서 -시-나 높임 어휘로 관계를 암시하지 않는다**(관계는 서술로만 밝힌다: '이야기 속 인물은 화자의 할머니다') |
| `sentence` | 목표 문장(평정 대상) |
| `critical_region` | 조작된 어절(예: `올라오셨어`). 분석·검수용 |
| `cq_question` | 이해 문항 질문(설계 파일의 `comprehension_question.template`). 해당 없으면 빈칸 |
| `cq_options` | 선택지 4개를 `|`로 구분. 설계 파일의 `options_rule` 순서대로 적는다(제시 순서 무선화는 실행 단계에서 한다) |
| `cq_answer` | 정답 선택지의 **글자 그대로** |
| `list` | 라틴 방격 목록 번호 `1`–`4`. 규칙: 세트 번호 s(1부터), 조건 인덱스 k(a=0, b=1, c=2, d=3)일 때 `list = ((k − s) mod 4) + 1`. E4는 빈칸 |
| `norm_status` | `적격` / `덜 선호` / `부적격` / `비표준` 중 하나 + 짧은 근거 |
| `note` | 제작 메모(관계 유형, 주의점). 인간·모델에게 보이지 않는다 |

E4는 세트마다 `violation`·`control` 두 행을 둔다. `cond`는 B1 세트면 `b1`, B2 세트면 `b2`로 적고 `A_level`은 비운다(판정어는 실행 단계에서 적용). 이해 문항 열은 비운다.

## 품질 기준

- **자연스러움**: 적격 조건 문장은 모어 화자가 실제로 할 법한 말이어야 한다. 번역투·교과서투를 피한다. 구어 해체·해요체는 구어답게.
- **최소대립**: 설계 파일이 '같아야 한다'고 한 부분은 **한 글자도** 다르지 않게 만든다. 스스로 문자열 비교로 확인한다.
- **다양성**: 설계 파일이 정한 유형 배분을 지킨다. 같은 서술어를 세 번 이상 쓰지 않는다. 다른 실험(E1–E4) 파일과 문장이 겹치지 않게, 이미 있는 CSV가 있으면 열어 확인한다.
- **이해 문항**: 정답이 하나로 정해져야 한다. 오답 선택지도 그럴듯해야 한다(명백히 틀린 선택지만 있으면 변별력이 없다).
- **규범 판정**: `norm_status`의 근거를 `note`에 짧게 남긴다. 판정이 애매한 세트는 `note`에 `검토 필요:`로 시작해 이유를 적는다 — 규범 검수 단계(P4-03)가 이 표시를 본다.
- **민감성**: 실존 인물·기관 이름, 차별·폭력·질병 비하 소재를 쓰지 않는다.

## 끝나면

1. `python3 build/validate_stimuli.py E?`가 있으면 돌려 오류를 없앤다(아직 없으면 건너뛰고 보고에 적는다).
2. 150단어 이내로 보고: 세트 수, 유형 배분, `검토 필요` 세트 목록과 이유, 설계 파일과 다르게 처리한 점.

git 명령은 실행하지 않는다. 맡은 CSV 외의 파일은 고치지 않는다.
